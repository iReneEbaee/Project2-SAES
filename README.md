# S-AES 编程实验

Python 3.10+，只使用标准库（含 Tkinter）。启动：

```powershell
python app.py
```

自动测试：

```powershell
python -m unittest -v
```

## 功能与操作

| 功能 | 操作 |
| --- | --- |
| 单分组加解密 | “基本 / 多重加密”页，单重模式，输入 16 位数据与密钥，点击加密或解密 |
| ASCII 字符串 | “ASCII 字符串”页输入 ASCII，按 2 Bytes 分组；密文提供 HEX 与 Latin-1 字符的 JSON 转义表示 |
| 双重 / 三重加密 | 选择 32-bit EE 或 48-bit EEE；从左到右拼接各 16-bit 密钥 |
| 中间相遇攻击 | 输入多行二进制明密文对，点击完整攻击；可载入示例、取消和导出全部候选 |
| CBC 与篡改对比 | 随机生成 IV、加解密长消息；翻转 C1 一位或自行替换密文分组，再对比结果 |

## 算法约定

S-AES 的分组和单重密钥均为 16 bit。四个半字节由高到低为 n0,n1,n2,n3，状态为 `[[n0,n2],[n1,n3]]`。HEX 数据均按高字节在前表示。

- S 盒：`9 4 A B D 1 8 5 6 2 0 3 C E F 7`。
- 逆 S 盒：`A 5 9 B 1 7 8 F 6 0 2 3 C 4 D E`。
- GF(2⁴) 模多项式：x⁴+x+1（0x13）。
- 列混淆矩阵 `[[1,4],[4,1]]`；逆矩阵 `[[9,2],[2,9]]`。
- 密钥扩展 RCON 为 0x80、0x30。
- 加密：AK0 → NS → SR → MC → AK1 → NS → SR → AK2。
- 解密按以上逆序执行逆变换。密钥扩展示例：2D55 → BCE9 → A34A。
- 单重已知答案：P=D728，K=4AF5，C=24EC；二进制为 P=1101011100101000，K=0100101011110101，C=0010010011101100。

双重加密为 `C=E_K2(E_K1(P))`；三重加密为 `C=E_K3(E_K2(E_K1(P)))`，解密反向执行。多重单分组不填充。

字符串与 CBC 使用严格 ASCII 明文编码、大端 2-byte 分组和 PKCS#7 填充：奇数长度补 01，偶数长度（含空字符串）补 0202。密文可能超出 ASCII，因此采用 Latin-1 一一映射字节，界面转义显示控制字符；跨平台传输推荐 HEX。其他程序须采用相同编码与填充约定。

## 中间相遇实验

建立 `E_K1(P)` 到所有 K1 的映射，再枚举全部 K2 比较 `D_K2(C)`；不丢弃中间值碰撞。其余明密文对用于过滤候选。单个 16-bit 明密文对通常无法唯一确定 32-bit 密钥，应增加不同的明密文对；程序返回的是满足观测的全部候选，不能保证这些候选就是原始密钥。复杂度约 O(2¹⁶ + 2¹⁶ + 候选验证)，存储 O(2¹⁶)。GUI 后台线程运行，最多每 1024 次迭代检查取消。

## CBC 篡改实验

IV 使用 `secrets.randbits(16)` 生成，公开但需要与密文一同准确共享；每条消息重新生成。`C0=IV`，`Ci=E_K(Pi XOR C(i-1))`，`Pi=D_K(Ci) XOR C(i-1)`。IV 不自动拼入密文，需要单独传输。

修改 Ci 会扰乱 Pi，使 Pi+1 对应位翻转，而后续分组不变；修改 IV 只影响首组对应位。界面对比不移除填充，便于观察末尾分组被篡改的情况；正常解密严格验证填充。可复制一个完整的 4 位 HEX 分组覆盖另一组来做替换实验。不同长度的消息对比也会标识缺失的分组。

S-AES 是教学算法，16-bit 密钥与分组不适合真实保密场景，CBC 本身也不验证消息完整性。

## 文件

- `saes.py`：纯函数算法、字节转换、CBC 与完整中间相遇攻击。
- `app.py`：Tkinter GUI，错误提示、后台攻击和候选导出。
- `test_saes.py`：密钥扩展与轮变换、已知答案、全明文空间往返、随机密钥、多重加密、填充、CBC 篡改及完整攻击测试。
- `README.md`：运行说明、算法约定与实验操作说明。
- `file/`：用户指南、测试结果等项目文档。

界面默认明文、密钥和攻击示例在 `app.py` 中设置，不依赖外部测试数据文件。
